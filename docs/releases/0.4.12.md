# Release 0.4.12 — Deterministic compaction-summary structure

**Coordinated packages:** `ds4-context-core`, `ds4-context-reference-adapter`, and `ds4-context-engine` 0.4.12.

## Changes

- DS4 now normalizes the twelve required summary sections before validation, on every segment, aggregate and direct update: recognizable headings are canonicalized, duplicate bodies are concatenated in encounter order, and the contract order is restored. Missing or empty semantic sections receive an explicit reporting-omission marker (`- Not reported in the generated summary; absence of facts is not established.`) instead of failing the whole graph, so a repairable Markdown omission no longer discards an otherwise usable compaction.
- Unknown headings and unsectioned text are retained as quoted notes in `Current State`; they are never promoted into decisions, constraints or completion claims. A whole-output Markdown fence is unwrapped. `Files Read` and `Files Modified` are always regenerated from Pi's sanitized file-operation inventory, including when their headings are missing or duplicated, and Markdown-unsafe known-file evidence still fails closed without leaking the path.
- Exact-value quote retraction now runs whenever unsupported spans are present, independently of other validation errors, and only when the summary fell back to fail-closed. Both repairs are reported as warning codes with counter-only messages: `summary-structure-normalized` and `summary-sections-not-reported`. No generated heading, path or body text appears in the diagnostics, and no additional provider repair request is issued.
- Adds the new core export `normalizeSummaryStructure`, verified by the engine↔core compatibility guard, plus synthetic regressions for all twelve sections (missing, empty, duplicated, reordered), heading-level/case/emphasis normalization, every JavaScript line terminator and heading whitespace form, unknown headings and free-form output, whole-output fences, canonical file inventories, unsafe evidence, empty responses, tool-call responses, idempotence, all 4,096 omission subsets, and segment, aggregate and direct-update coordinator paths. Each combined-failure regression reproduces the reported `missing-section, unsupported-exact-value` error on the prior implementation.

**Implementation commit:** `bcc0a02`. Decision: [ADR 072](../ADR/072-deterministic-summary-structure.md) (supersedes ADR 069's structural-fallback policy).

## Scope and limitations

The problem was reproduced locally from code and tests; the reported live failure is not confirmed to have recurred after this patch, and no live session, database or session JSONL was inspected. Normalization preserves what the model reported: it cannot recover facts that were never reported, and the omission marker states that absence is not established. Unrecognized section titles remain notes rather than being guessed into a semantic category.

The strict validator and its error severities, the eight-bullet bound, the 25% removal limit, output-limit handling, transport retry policy, graph atomicity, JSONL authority and persistence schemas are unchanged. Empty responses, tool-call responses, unsafe file evidence, incomplete transport, output limits, aborts and storage failures still fall back to Pi. No provider repair request is added. The summary contract version, default tokenizer, opt-in BPE/auto-tuning, privacy enforcement and provider-facing defaults are unchanged. Core and the reference adapter receive only the coordinated version bump.

No live-provider, real-compaction or Windows-host confirmation is claimed, and the separate real-context BPE/auto-tuning objective remains open.

M5 Hierarchical Summary Graph completato.

Implementato:
- ogni compaction crea un segment node immutabile del solo nuovo span scartato
- compaction successive generano un aggregate node bounded da [previous active root, new segment]
- active root risolto esclusivamente da preparation.previousSummary + event.branchEntries; niente recency session-global
- import esplicito warning-level dei precedenti summary Pi non DS4 come branch node
- metadata Pi schema v2 backward-compatible con M4 schema v1
- active summary in CompactionEntry.summary; nuovi nodi non attivi embedded nei details per rebuild canonico
- kind, graphLevel, ordered child IDs, segmentSummaryId e hash transitivo
- hash segment su source canonica diretta; hash aggregate su ordered child IDs/kind/level/source hash
- sourceEntryIds transitivi e file provenance cumulativa
- generazione e validazione separate per segment e aggregate; usage delle due chiamate sommata
- batch SQLite atomico prepared/committed/failed
- migration v6 con graph_level e child_order
- SummaryRepository graph-aware: edge ordering, same-session children, increasing levels, cycle guard, immutable ID collision rejection, metadata/link integrity
- crash/rebuild replay completo da Pi JSONL; schema-v1 normalizzato come segment L0
- correlazione post-commit per pending summary ID, workaround Pi 0.84.3 quando summary text duplicato restituisce entry precedente
- in-memory graph per sessioni ephemeral
- /context summaries con roots, active branch path, livelli, lifecycle e provenance counts
- docs SUMMARY_GRAPH, compaction, architecture, storage e ADR aggiornati
